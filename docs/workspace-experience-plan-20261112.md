# 工作区滚动整改与项目入口功能评估

日期：2026-11-12。范围：Agent 工作区管理、项目历史列表与正文预览。用户已选择后续功能优先级为「进入项目：打开目录、继续会话」。本记录承接已授权的页面整改，不改写上一轮人工 A3/A4 验收。

## 已实施的体验调整

原布局将项目目录和历史纵向堆叠，同时允许主页面和限高正文分别滚动。目录多时历史在首屏以下，打开正文还会推动外层页面；用户难以判断滚轮控制哪个区域，分页与项目切换也会离开视口。

现在采用开发工具常见的固定导航与独立内容区：

| 区域 | 新行为 |
| --- | --- |
| 工作区页头、顶层视图、当前项目标题 | 保持可见；工作区内容不再推动应用主页面 |
| 项目树 | 项目列表独立滚动，搜索框固定 |
| 项目详情 | 分「会话历史 / 项目目录」两个视图，默认显示历史 |
| 历史列表 | 列表滚动，搜索、筛选及底部分页固定 |
| 正文预览 | 在列表区域内替换显示，消息滚动，返回与消息分页固定 |
| 返回与刷新 | 返回列表恢复原位置与触发按钮焦点；切换目录视图再返回保留位置；普通刷新保位，筛选或翻页从页首开始 |
| 请求等待 | 保留原列表以稳定布局，显示更新状态，禁止打开旧结果 |
| 来源诊断 | 默认折叠；摘要提示未就绪来源，展开后限制诊断区高度，保留正文空间 |
| 窄容器 | 工作区容器宽度不大于 680px 时，项目树改为「当前项目」选择器 |
| 较矮窗口 | 720px 以下压缩页头间距、隐藏辅助说明，让标题和操作排在同一行，为列表留出阅读空间 |
| 目录清单 / 待确认 | 各自滚动；目录清单表头固定 |

项目树、目录、历史和消息区使用 `overscroll-behavior: contain`，到边界后不向外层传递滚动。可键盘滚动的内容区有可见焦点。布局使用 `min-height: 0` 与剩余空间分配，移除正文原有的 `58vh / 560px` 限高。

以上依照既有产品字号、控件、颜色令牌，沿用原 UI 审查的响应式容纳性、WCAG 2.2 键盘操作/焦点与状态反馈要求；未引入新的视觉体系。

## 项目入口：本次已经交付

- 项目标题增加「打开目录」：单目录直接打开；多目录进入「项目目录」视图，用户明确选择路径。
- 各路径增加「打开目录」「复制路径」。未关联目录的项目不出现无效入口。
- 打开复用 `agentApi.openFolder → open_folder → system.folder.open`，复制使用剪贴板 API；提供进行中、成功、失败反馈并禁止重复操作。

本次只新增上述入口，没有把新建会话或打开目录标为「恢复原会话」。历史适配器的 `can_resume` 仍然是 `false`。

## 继续会话：可行性与实现方式

### 1. 在项目中进入 HiMind AI

现有 `start_builtin_ai_session` 接受 `workspace_root`，会验证真实目录，并以指定目录进入 Runtime。可以复用此链路实现项目级「进入 HiMind AI」。多目录项目需选择或设置默认目录；后续返回项目仍保留原筛选和阅读位置。

需要先给 `BuiltinAiWorkspaceTarget` 增加通用工作区项目类型，清楚保存登记项目 ID 与目录。不能把工作区登记 ID 直接当成现有扩展项目 ID，也不宜直接调用 `openExtensionWorkspaceAi`：后者有扩展开发工具准备和插件/技能刷新副作用。

这一入口按目录继续工作；现有启动命令没有选中历史记录的 `native_id` 参数。精确恢复 HiMind 历史需进一步确认 Runtime 的会话选择/深链契约。

### 2. 恢复指定 Claude Code / Codex 历史

本机 CLI 帮助确认：Claude 支持 `--resume <session-id>`，Codex 支持 `resume <SESSION_ID>` 与 `--cd <DIR>`。统一历史模型已经保留 `source`、`native_id`、`working_directory`，具备启动适配基础。

建议第一版在原生客户端终端中恢复，保留客户端自身的模型、认证与工具交互。实现应包含：

1. 后端按稳定历史 ID 重新查找来源及原生 ID，重验项目归属与目录存在性，不信任前端提交的任意命令。
2. 探测客户端可执行入口和所支持的恢复参数；Windows 的 `.ps1/.cmd` 包装入口与直接可执行文件分别适配，避免把路径和会话 ID 拼成 shell 命令。
3. 用该条记录的真实原生 ID 和明确工作目录启动；不使用 `--last` 或 `--continue` 替代用户选中的记录。
4. 按「来源 + 原生 ID」限制重复启动，处理未安装、目录失效、会话删除、版本不支持和启动失败。
5. 根据实际可观测状态显示「客户端已启动」等反馈。仅进程启动成功不能证明原客户端已经完成恢复；若需要显示恢复成功，必须增加客户端握手或协议确认。
6. 能力由后端按来源和客户端状态计算，界面只对满足条件的记录提供「继续会话」。原只读索引仍不写入客户端历史。

不要把历史文字复制到新对话并称为恢复：这不能还原工具状态、授权状态及原会话身份。

## 优先级与工作量

估算以一位熟悉现有 TypeScript/Rust/Tauri 架构的工程师为基准，1 工程日约 8 小时，包含实现与对应回归；不含等待外部 Runtime 接口、客户环境验证和发布。下表是新增功能估算，不是本轮已经消耗的工时。

| 顺序 | 功能 | 预计工程日 | 用户价值与依赖 |
| --- | --- | --- | --- |
| 已交付 | 打开目录、复制路径与滚动整改 | 本轮完成源码及浏览器验证 | 找到项目后直接访问文件，长列表不丢导航 |
| P1 | 通用项目「进入 HiMind AI」 | 2–3 | 复用目录启动能力，补项目类型、目录选择、导航回还和失败状态 |
| P1 | Claude / Codex 恢复指定历史，原生终端 | 4–6 | 共享启动适配层、两类来源恢复、能力探测、异常处理、路径/ID边界与原生联调；依赖可用客户端 |
| P1 | 默认目录、最近访问与返回上次项目 | 1–2 | 多目录项目不反复选择；持久化 UI 偏好，处理失效路径和登记变化 |
| P2 | 常用项目置顶、最近活动排序 | 1–2 | 大量项目时快速找到常用项；活动时间复用历史元数据，避免逐条读正文 |
| P2 | 失效目录检查与重新定位 | 1–2 | 复用已有校验能力；重新绑定需保留原路径历史归属并明确冲突处理 |
| P2 | 会话收藏、备注、隐藏 | 2–3 | 使用 Agent 自有覆盖元数据，不改原客户端历史；处理来源删除与 ID 稳定性 |
| P2 | 项目关联任务与产物 | 3–5 | 需要登记项目与任务系统统一 ID/路径映射及迁移约定 |
| P3 | 正文全文搜索与命中定位 | 5–8 | 新增增量索引、文件变化检测、删除同步、损坏恢复和结果定位；不能每次搜索扫描所有正文 |

建议下一阶段先完成前三项，合计约 **7–11 工程日**，再预留约 20% 的 Windows 客户端兼容与交叉回归时间，规划 **9–14 工程日**。该范围只包括 HiMind 项目目录入口及 Claude/Codex 原生终端恢复；不包含五来源统一内嵌会话编辑器。

若要求在 Agent 内继续所有来源的原生会话，需另立 Runtime/执行器协议集成阶段。对话输入、工具确认、流式重连、运行状态和跨来源身份都要统一，仅凭 CLI 恢复命令不能可靠给出该阶段的工期。
