当前只有四类有效通用职责覆盖：技术架构、软件实现、界面交互和测试质量。
“需求与产品设计”尚无对应独立专家包；系统应展示该能力缺口或在现有专家明确声明的
能力范围内采用有限方案，不虚构已安装产品专家。游戏/展项等领域专家也未出现在本机
这一目录中，不能声称已具备。

## 发现的版本解析缺陷

原目录实现先按专家 ID 去重，再返回版本；选择取决于文件系统枚举顺序。
同一函数被精确版本查询复用，使旧版本可能在查询前已被丢弃。默认版本还使用字符串
比较，无法正确排序 1.9.0 与 1.10.0。当前开发投影若覆盖相同版本，按版本查询也无法
保证读取历史 Mission 原摘要对应的发布内容。

实施修复采用两条读取路径：默认专家目录仍一身份一条（显式开发投影优先，否则取最新
语义版本）；指派目录及 Mission pin 保留所有可解析版本并以摘要区分内容。
新任务推荐收敛与存储删除分开：合并推荐身份不删除、重写或自动升级旧任务绑定。

## 后续验收

版本、摘要、推荐重复身份分别运行契约测试；真实能力质量需用特定专家/技能版本、执行器、
模型、工作区和任务样本评测。资产“已安装”及目录结构通过不能替代行为能力验证。
