# 工作区项目层级与会话历史

## 项目身份与导航

项目别名是界面的主身份，磁盘目录表示物理位置。登记名包含中文时优先显示；否则唯一中文别名可作为显示名。多个中文别名需要用户明确选定，选定前回退登记名；没有中文配置不自动翻译。原技术名、其他名称和目录仍可搜索。更改别名保留项目 ID、目录绑定 ID 和会话 cwd。

左侧导航只显示单行别名、父子层级和子项目数，技术名放在悬浮提示，完整路径和目录数量放在详情。搜索保留匹配项的祖先，子项目数始终表示实际直属子项目数。

父项目默认进入子项目列表，叶节点默认进入会话历史；用户选择的详情视图按项目记忆。面包屑和窄窗祖先选择器支持进入子项目与返回父级。逻辑层级不要求目录在磁盘中嵌套。

## 范围与历史读取

详情的“仅此项目 / 包含子项目”统一控制目录、五来源会话列表、来源计数、正文搜索和相关文件搜索。会话统一去重、排序后分页；预览、复制恢复命令和继续会话使用真实所属项目，不能把父级汇总范围当作操作归属。

来源包括 HiMind AI、ACP、Claude Code、Codex 和 OpenCode。HiMind AI 仅使用已持有 Runtime 的控制接口；其它来源按各自约束读取本机记录，正文按需分页，不复制进工作区登记表。缺失、损坏、部分读取及扫描限额均显式反馈。

支持正文搜索、用户提问导航、单条复制、历史工具记录中的相关文件与补丁/片段对照。文件记录是历史请求证据，不代表工具执行成功或当前文件状态。正文和历史内容均按文字显示，不能作为执行指令。

Windows 下检测到 Claude/Codex 原客户端时可继续指定会话或复制 PowerShell 恢复命令。后端重新解析会话、验证目录与当前归属，限制恢复 ID，避免嵌套 cmd 解析并抑制重复启动。其它来源暂不提供原客户端恢复。

正文、列表、项目树和目录分别管理滚动；返回列表保留位置。窄窗采用单栏项目选择，极窄或极矮窗口允许内容滚动以保留操作和阅读空间。编辑、整理及确认使用模态焦点管理，关闭后恢复焦点。

## 目录整理与一致性

可以新建子项目，或把父项目已有目录批量整理到具名子项目。先生成整体预览，再校验登记 revision、名称冲突和重复入口，原子保存；首次目录和新项目也在同一事务中保存。新节点不复制父项目的外部链接。

整理保留已有目录入口 ID 和路径，并生成独立恢复快照。恢复要求当前 revision 与整理结果一致，拒绝覆盖后续登记变更。历史搜索任务也校验 revision，避免归属变化后继续执行过期操作。

实现不自动迁移真实登记、不重命名磁盘目录、不创建重复的跨盘或符号链接项目。具体中文名称和项目归属由用户在界面中选择并保存。

## 验证

前端在 `frontend` 中运行：

```sh
npm run check:workspace-project-model
npm run check:workspace-hierarchy-browser
npm run check:workspace-ui-browser
npm run check:session-history-browser
npm run build
```

浏览器回归使用内存合成 API。工作区回归需要先把 `WORKSPACE_SOURCE_WIRE_FIXTURE` 设为 `target/workspace-source-wire.json` 的绝对路径，再运行 Rust 的 `source_wire_keys_match_filter_ids_and_accept_legacy_opencode` 测试，生成实际序列化的来源样本；浏览器回归沿用同一个环境变量读取样本。浏览器脚本支持 `PLAYWRIGHT_MODULE` 和 `CHROMIUM_EXECUTABLE`，层级脚本也可使用本机已安装的 Chrome。

Rust 可分别按 `workspace_registry::`、`session_history` 和 `store::acp_sessions::` 过滤测试。测试覆盖中文名回退、路径匹配、父子范围、来源隔离、分页游标、归属变化、恢复参数、搜索取消/限额、整理冲突与保护恢复。

合成检查覆盖 320px、768px、小窗、等效 200% 重排、键盘和独立滚动。合成命名与导航已获人工确认；原生 WebView 的实际缩放、焦点与滚动，以及真实客户端续接，仍需安装新版后的人工验收。源码提交不代表已经部署。

来源配置、分页和限制详见 [工作区会话历史](workspace-session-history.md)。
