### 可操作核心用户路径（设计建议，非本次已跑通）

1. **首次接入服务与客户端**：设置 → AI 连接 → AI 服务 → 新增服务 → 填名称/连接/凭据 → 选能力与模型 → 保存 → 能力路由选该能力默认与备用 → 工具接入展开目标客户端 → 选择直连或网关并分发/更新。完成标志应分成「定义已保存」「配置已同步」「请求已验证」三项，不能一个已就绪全部代替。保存失败留在当前步骤并保留非密钥输入；自检仅在用户明确选择后运行，说明可能发起请求。
2. **改变对话默认但保留任务特定选择**：能力路由 → 对话 → 默认服务 → 模型选跟随服务默认或显式模型 → 查看备用顺序 → 保存并确认作用域 → 工具接入查看需要更新的客户端 → 我的任务 → 详情/专家指派核对该任务显式执行器、服务、模型。没有解析证据时不宣称旧任务自动继承；变更前后记录来源，取消编辑不保存。
3. **预算或命令环境等待后继续（以下目标路径须以本轮跨层决策为前提，不保证当前入口可执行）**：我的任务 → 待我处理 → 对应任务 → 先读原因/行动者/下一步 → 预算用尽选增加预算并继续，环境阻塞选处理命令环境，主动暂停选恢复任务，系统核验排队显示无需操作 → 提交后回同任务确认新状态。环境授权不等于 OS 沙箱授权；不要用一般重试绕过预算或审批。未知等待原因只引导查看详情。
4. **核验失败定位与恢复**：我的任务 → 失败或需处理任务 → 查看失败子任务 → 查看提交文件、必需检查真实结果、独立核验结论 → 原实现可重核时选重新核验同一实现，否则生成跟进任务 → 回任务追踪。显示哪些步骤会重复执行，避免把「继续原运行」「重做实现」「重新核验」混为重试；测试输出缺失写未提供。
