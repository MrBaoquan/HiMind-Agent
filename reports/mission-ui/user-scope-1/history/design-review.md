## 设计结论与假设

按最保守场景处理：用户每天在桌面工作区重复查看多专家任务，先判断“是否需要我处理、谁在做、下一步是什么”，再查证据；未获得额外用户访谈或品牌要求。方向是克制、密集，保留现有任务列表、四个详情页签、浅色令牌和原生对话框。记忆点是同一交付下并列的“实现结果 / 必需检查 / 独立验收”，每列同时显示运行号、记录 ID、实际时间。设计参照是 GitHub Checks 的运行结果与重新运行历史；本产品额外区分实现与另一位专家验收。此处为结构参照，未进行外部竞品实测。

来源优先采用任务契约 B08/B09、后端 `mission.wait.v1` 与现有 `frontend/styles.css`；没有加载未固定外部技能，没有新增组件库或改变业务接口。状态资格由后端投影提供，事件仅作历史，避免最后一条进度或反馈覆盖预算等待。

## 结构与主路径

- 列表、待处理入口、详情共用已确认计划、原因、处理者与快照 cursor；旧 cursor 不覆盖新状态。详情事件分页面对全局序列号，不把跨 Mission 的序号间隔误当丢数据；读取不完整或关联错误时关闭增额/恢复资格。
- 当前行动区先显示原因、责任和下一步；预算等待的主操作为“增加预算并继续”，环境阻塞为“处理命令环境”，暂停为用户可选续跑，核验阶段为查看详情。其他操作收进“任务操作”。无执行者的协调间隔显示“状态待核对”，只展示最近观察记录与时间。
- 预算对话框展示全部五种限制，追加值默认零；响应丢失后的原参数重试保留申请号和原请求。更改参数会明示这是新申请。成功后再次读取当前暂停/环境状态，不能把成功增额等同恢复成功或完成。
- 概览始终展示已有交付。按原始交付计算进度，重做归入其父交付；成环或缺父项单独保留，不算额外业务完成量。展开查看所有历史尝试和事件，不擦除失败。缺正文/退出码/汇总明确标缺，不捏造通过数量。
- 续跑继续未完成任务；重核重跑同一实现的检查与独立验收；重做按跟进方案修改对应交付并保留历史。保留已有可选重核、生成跟进任务入口。

## 六类状态

|状态|界面表现与检查范围|
|---|---|
|加载|任务列表与详情读数前显示读取反馈；真实浏览器验证列表加载，未把零任务当加载结束。|
|空|无任务和筛选无匹配分开；无正文、无关联验收、未知用量也分别说明。|
|错误|读取错误用 alert；增额失败保留参数和申请号；快照关联不一致关闭恢复和增额。错误为传输边界样本。|
|部分可用|总体未完成仍能展开已有交付、必需检查和验收；某列缺正文仍显示真实运行/记录/时间。浏览器使用真实 Store 持久化状态种子。|
|成功|增额确认后显示当前状态；整体完成保留所有证据入口。预算事务真实执行，完成/核验结果是明确标记的契约种子，未真实执行专家。|
|无权限|传输拒绝样本显示读取失败告警，不展示虚构数据；未验证系统账号权限或生产授权链路。|

预算耗尽后追加 task_progress、环境阻塞、手动暂停、核验已派发、协调重试、真实 running、部分交付、核验失败、全部完成均有浏览器记录。只有任务正在执行、关联核验运行实际上报 running 或当前操作请求执行时才展示运行反馈；仅有历史事件/运行号不推断活跃进程。

## 取值与依据

- 沿用字号 12 / 13 / 14px：元信息 / 正文 / 三列证据标题，正文行高 1.6。采用现有 4 / 8 / 12 / 16 / 24 / 32px 间距阶梯；三列列距 16px、元数据行距 8px、证据段落上下距 8px。
- 大于 900px 时证据三列，900px 及以下单列；预算项最小宽 220px，窄屏退到可用宽。ID、路径和正文允许断行，长正文最多 360px 高后内部滚动；没有截断事实字段。
- 按现有令牌：控件圆角 6px、弹层 8px；证据记录不增加阴影，现有弹层阴影继承，未创建新档位。Mission 操作目标至少 36px 高，证据 summary 至少 40px 高；焦点描边 2px。
- 已有运行脉冲 1800ms ease-out，仅实际运行时启用。减少动效下 Mission 与预算弹窗禁用动画，过渡仅允许透明度 100ms，继承现有缓动。刷新周期 5000ms，前台可见时读取。
- 使用现有正文 #171a1f、次要文字 #5b616b、主色 #1f4e79、白色背景和浅色表面。`result.json` 保存这些已使用令牌的计算对比度；这只是所列色对的数学验证，不代表整页或全部交互满足 AA。真正深色主题未实现，系统深色偏好下保留项目既有浅色策略。

## 渲染与独立立场复核

最终证据目录由 `result.json.render_evidence` 指定；保存原始接口转录、浏览器断言、截图和候选文件前后哈希。实际检查 1280×900、640×900、390×844、320×800，长路径、200% CSS zoom 与 640px 等效响应布局；系统深色偏好、减少动效；预算对话框原生模态 Tab 路径。桌面三列和 390px 单列截图已逐张查看，未见水平溢出，缺正文标签、run/id/time 清晰可读。

从独立评审者立场重新核对：预算资格不依赖事件尾、计划/cursor 不匹配关闭资格、同键重试不重复增额/派发、后来的暂停不被旧响应覆盖、币种不可比较时不汇总、未知计量不补零、修复不扩大进度分母、当前运行与历史失败不混淆。此为作者再次复核，不能冒充外部独立专家验收。最终回归也保留既有服务界面断言及普通/隔离构建兼容检查；服务任务先前的双模式构建修复不记本次成果。

## 能力限制和风险

浏览器运行生产 React 组件、实际 agentApi 参数封送；只在 Tauri 传输边界接隔离 JSON 桥，调用未经修改的 Store/contract/candidate 源码及原检查参数解析器。SQLite、构建、截图、缓存均在宿主专用资源根。无真实账号数据、无生产服务操作。

探针为测试程序，非完整桌面应用：无关的专家/工作流/模型依赖使用失败关闭的桩，未执行这些路径；核验与检查正文为明确标记的状态种子，不是实际模型/专家输出。未验证打包 Tauri/MCP 链路、真实跨执行器专家核验、原生浏览器菜单缩放、完整读屏路径、真正深色配色、全部色对、生产部署及正式 VERIFY。B08 F01–F10 后端完整竞态矩阵属于后端/QA 交付，本阶段没有宣称全部执行。用户场景假设若不成立，需要重新评估密度；服务端 DTO 若改版或缺失，本版本保守显示未知并关闭恢复资格。

开发过程中的失败保留在资源根，包括首次浏览器路径过长、默认 Chromium 缺失、旧状态断言和测试种子修正；不以最终通过掩盖早期失败。
