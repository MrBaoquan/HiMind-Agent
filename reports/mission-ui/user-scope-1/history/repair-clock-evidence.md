# 统一预算时钟与子任务交付证据

本阶段代码与检查已就绪；实际退出码以 result.json 为准。passed 仅表示本任务送验建议，没有执行宿主正式 VERIFY、真实专家核验或生产部署。上轮结果和失败保留为历史。

## 设计结论（clarify → direction）

保守假设：用户反复在桌面查看多专家协作任务，先判断预算是否耗尽、已有交付能否查看，再核对具体运行。沿用项目设计系统与浅色令牌，方向克制、密集。记忆点是每个子任务均能按“实现结果 / 必需检查 / 独立验收”查到运行号、记录 ID 和时间。结构参照 GitHub Checks 的尝试记录，本产品另列实现与专家结论；未做外部竞品实测。

契约优先：只修指定前端范围，不加载未固定外部技能、不新增依赖、不修改后端门禁、接口或数据模型。用户场景和额外品牌要求未提供，按上述假设推进。

## 结构与状态（structure）

概览和预算弹窗接收详情组件同一个 now。确认后每 1000ms 更新，active→waiting 不清理时钟。计算遵循 src/mission/store.rs 的确认至当前墙钟语义：负差归零、整分钟累计、累计值 >= max_minutes 即耗尽。手动暂停、环境等待、预算等待、核验等待均继续累计。核验中的增额资格限制保持后端原规则。

MissionView 没有预算结算终点；updated_at 未约定为结束时间。因此终态不冻结，明确说明“确认至今的累计时间，不代表结算运行耗时”。实际验证 completed 后继续累计；failed/canceled 走相同路径，无独立冻结分支。

概览保留三列，子任务行提供三个原生 details 入口。只展示该行当前实现和核验运行对应记录；返工谱系另展开，原失败和同一实现前次核验失败均保留。按 mission_id + task_id + 非空运行号关联；检查要求 plan_sha256、implementation_run_id、verification_run_id 一致且实现/核验运行不同。不以实现提交或 task.completed 补造独立验收通过。缺正文、记录、时间、运行号或汇总明确标未提供，不推测 TAP 总数。

## 取值与依据（spec）

- 沿用 12/13/14px 元信息、正文、证据标题，行高 1.6；间距 4/8/12/16px；概览列距 16px、元信息行距 8px。依据既有 Mission 样式，不生成新设计系统。
- 行证据 summary 最小高 40px，内边距 12px 4px，焦点描边 2px；已有任务操作最小高 36px。实际键盘 Enter 与焦点样式有断言，不声称完整无障碍合规。
- 概览 >900px 三列、<=900px 单列；子任务证据始终单列。预算项最小 220px 并受 100% 可用宽约束；ID、正文、引用换行，正文最大高 360px 后滚动。
- 继承控件圆角 6px、弹层 8px、现有弹层阴影；证据入口无新增阴影或动效。减少动效继承 animation:none 和 opacity 100ms 规则。
- 状态轮询 5000ms、时钟 1000ms。本机时间仅供展示，服务器仍复核资格，不因客户端显示自动放行。

## 复核、假设与风险（deliver）

作者从评审者立场再次检查：预算两处无独立 Date.now 默认值；等待不停止时钟；耗尽用 >=；不以 updated_at 编造终点；证据限制 Mission/任务/计划/运行；缺失事件不靠空运行号命中；失败历史不被当前成功擦除。此为作者复核，不是独立专家验收。
